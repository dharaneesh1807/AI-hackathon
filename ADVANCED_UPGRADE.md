# Catalyst ElderCare — Advanced Edition

This cumulative upgrade includes Premium Edition (display-name and profile editing, responsive design, seven-day insight chart and branded HTML email) plus RefillGuard, Care Report, Care Command Center and optional Voice Escalation. No extra Python dependencies, no changes to existing columns, no secrets or database files in the archive. On startup SQLAlchemy creates three additional tables (`medication_supplies`, `voice_preferences`, `voice_attempts`). Back up local data; production migrations and a managed database backup policy are required before real-world deployment.

## Install

Extract the ZIP into the existing project root, not a nested folder. Replace matching files. Stop the local server first and run `python -m pytest -q` (19 tests). Start with `python -m uvicorn backend.main:create_from_env --factory --reload`. Check the homepage, log in, and visit the three new navigation items. Commit the changed source and tests to GitHub, excluding `.env`, database files, and credentials; deploy latest commit on Render. Keep existing Render database and secrets. Copy the entire updated `google-integration/Code.gs` to the existing private Apps Script and save; retain existing Script Properties and five-minute trigger. Existing email reminders continue working without voice settings.

## RefillGuard

Enter remaining prescribed dose units (not tablets, milligrams or dosage amounts) and a low-stock threshold in days. Remaining / daily schedule count estimates days of supply. A new confirmed-taken report deducts one unit; repeated confirmation is idempotent. Skipped/unconfirmed reports do not deduct stock. Owner/caregiver can reconcile inventory manually; family can view. Estimate assumes the existing daily schedule and user-entered stock, not a medical recommendation. Refill tracking does not send separate refill emails in this release.

## Care Report and Command Center

Report uses authorized database queries for the last 7 or 30 rolling days, current schedules, upcoming appointments, and up to 20 unresolved follow-ups. Confirmation rate is reported taken / recorded due doses; it is not evidence of actual ingestion or clinical adherence. Print / Save PDF uses the browser print dialog (choose Save as PDF); the report contains health data, so use fictional data and share only with consent. The command center groups unclaimed and claimed follow-ups, shows low supplies, and highlights dose conditions eligible for voice escalation. It is rule-based, not clinical AI risk prediction.

## Optional real phone calls (Twilio Programmable Voice)

By default no phone calls can be sent. Email scheduling remains independent of telephony. Real calls require a Twilio account, an authorized voice-capable sender and a consenting, verified test recipient. Check country-specific/trial constraints and pricing: https://www.twilio.com/docs/usage/trials/try-out-voice and https://www.twilio.com/en-us/voice/pricing/in. Do not pay or upgrade solely for the hackathon unless you choose to. Some trial accounts require the provider's template (which will play generic demo content rather than our custom message); India availability and destination restrictions may prevent a live test.

1. In Twilio Console, verify a number you control, obtain the permitted voice-capable sender and check the Voice trial or paid setup. Never send unsolicited calls.
2. In Render service Environment, set `DEMO_VOICE_RECIPIENTS` to a JSON object mapping an approved demo account's login email to that account owner's verified consenting phone number in E.164 format. Example only: `{"test@example.com":"+12025550123"}`. Use real consenting test number, not this fictional example. Optional `VOICE_ESCALATION_MINUTES=60` (30–720; default 60, measured from scheduled dose). Save and deploy.
3. In your private Google Apps Script Script properties, retain `APP_URL` and `SCHEDULER_SECRET`. Add `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER` from Twilio. For restricted trial calls that require an official template, set `TWILIO_TRIAL_TEMPLATE=true` (generic provider demonstration voice). Otherwise omit it for custom privacy-minimal ElderCare TwiML. Never share secrets or put them in Git.
4. In ElderCare, sign in as the approved test account. Settings → Manage voice escalation → On → Save. This is per-profile consent. Call requests use a masked number display; approval is administrator-managed, not proof of email ownership. Only use accounts/inboxes/numbers under your control and fictional care data.
5. A scheduled dose becomes unconfirmed after 30 minutes. Once it reaches the configured threshold, still has an open (unclaimed) follow-up, and is no older than 24 hours, the scheduler can create a call request. One request per opted-in account per rolling 24h and one per dose/account; no automatic retries of ambiguous requests. A claimed or resolved follow-up or confirmed dose is excluded at queue time; a request already dispatched cannot be recalled. Test with a fictional dose and run `runCareReminders`. Check Apps Script executions and Twilio Voice logs. Status `accepted` means provider accepted a request, not that a call connected, was answered or delivered; `failed` means failure/uncertain transport, no automatic retry. Provider credentials are in private Script properties, not Render or Git. The same five-minute trigger handles calls and emails; timing is best-effort.
6. Disable the call opt-in or remove the provider properties to stop future calls. Remove the trigger if the demo is over.

## Validation and limitations

19 pytest tests passed (including prior 15 and 4 new tests: inventory idempotence, report authorization, voice timing/opt-in, deduplication and cancellation before dispatch). Both JavaScript files passed Node syntax checks. Tests use SQLite and injected clocks; no live Twilio call was placed. Verify browser rendering, production PostgreSQL and actual voice delivery separately. No clinical decision-making, emergency monitoring, verified identity, guaranteed delivery, or medical-device claims. Do not use actual healthcare data on this public demo. No changes to medication dosages are recommended by the software.
